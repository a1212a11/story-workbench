# 框架验收规格

状态：待实现、待执行；不是测试通过报告。对应 [架构提案](prd-story-framework.md) 第 6 节和 docs/requirements.md 的 A01–A19。

测试实现使用少量流程集成检查，不按每个函数铺测试。固定模型替身用于故障与权限；真实模型输出由人核对，不混成确定性成功。

| ID | 输入/操作 | 必须验证的结果 |
| --- | --- | --- |
| T01 | 同章保存两稿，检查第一稿后尝试采用第二稿 | 正文均可恢复；第二稿不能复用第一稿审阅；A11 |
| T02 | 对同一已审阅版本重复采用，再恢复另一历史内容 | 重复不新增正式采用；恢复保留历史、生成恢复版本并走采用；A07、A08 |
| T03 | 外部修改工作副本；再模拟数据库保存后文件写入失败 | 采用/生成前发现变化；原采用不变；恢复不覆盖外部新内容；A18 |
| T04 | 用作品甲的版本或检查 ID 对作品乙发起采用 | 应用与数据关系拒绝跨作品引用，无部分写入；R01 |
| T05 | 中文多行输入、粘贴、光标修改、保存和取消；存在两个候选稿时说“采用那版” | 无 Markdown/文件路径要求；取消不保存修改；歧义须定位，且没有生成采用记录、没有改变采用指针；明确当前稿的已读采用只需一个动作；A19、A11 |
| T06 | 按三章走查写正式稿、拒绝开锁稿、试写第三章并采用 | 最少输入足够；试写列假设；下一章上下文只有采用稿；每次正常写作请求执行一次正文生成及一次检查/候选提取，不自动自改循环；作者要求重写或失败重试另行计数；A01–A04、A17 |
| T07 | 检查返回缺字段、假引用；再用真实模型检查传闻、开锁能力与推理不足样本 | 无效结果标未完成并阻止采用；有效格式不等于语义正确，人工逐条记录命中与遗漏；A05、A16 |
| T08 | 写第二章时库中已有第三章事件；构造超限上下文 | 不将第三章知识当第二章事实；必要依据不能容纳时不发起生成；记录未纳入范围；A10 |
| T09 | 候选提取失败、采用后重算失败、取消后迟到结果、重算期间重新采用、保存失败 | 按阶段保留已确认保存内容；不重复采用；旧任务不能覆盖新依据；依赖生成暂停；A08、A13 |
| T10 | 回改第一章并采用，修订第二章，第三章正文不变 | 第三章重新检查、更新依据并解除已解决影响；无第三章新正文/重复采用；仍有问题时保留待复核；A06、A13 |
| T11 | 备份后恢复到新目录，比较正文、采用指针、检查与状态来源、任务阶段 | 内容与引用一致；不含密钥；能从未完成阶段重试；恢复不覆盖原项目 |
| T12 | 作者对候选稿反馈“没意思”，请求诊断并试改，决定保留/拒绝 | 输出问题证据和修改方案；需授权设定明确列出；原稿不被覆盖；作者对段落的反馈不擅自变整书规则；记录全文、选择理由、用量与耗时，允许质量结论为不满意 |

未来执行方式：实现后以一个标准库测试入口运行上述确定性流程，例如 `python -m unittest discover -s tests`（当前尚无此入口）；再人工走 T05 和 T12，保存交互记录与问题清单。真实模型 T07 只报告该样本的结果，若有遗漏须保留并修正验证，不能以格式测试替代。供应商费用与上下文限制需配置后才能做真实调用。

首期只验证主分支。A10 中分支隔离与 A14 已发布补救在 M3 另增验收，不声称本规格覆盖完整 V1。性能阈值、整书字数与作者满意度提升尚无基线，不能虚构数值；先收集样本再制定发布质量门槛。
