## 阶段依赖与交付顺序

| 阶段 | 前置条件 | 交付物与阶段出口 |
| --- | --- | --- |
| P 开发准备 | D01–D06 | 项目规则、可运行测试入口；各接入决策有明确完成时点 |
| S 保存与采用 | P01–P02 | 真实 SQLite/文件上的保存、审阅、采用、恢复；T01–T04 |
| C 作者入口 | S 阶段、P03 | CLI 普通文字创作入口；T05 手动验证 |
| G 生成与上下文 | S 阶段；真实调用另依赖 P04；G06 另依赖 R01 | 固定客户端先验证任务合同，再接供应商；有正式状态后验收 T06–T08 确定性部分 |
| R 回改与失败恢复 | S 阶段、G01–G04；不等待 G05/G06 | 重试、复核、备份恢复；T09–T11 |
| V 首个可用闭环 | C/G/R、P04–P05 | 真实三章流程、语义样本和作者反馈记录；首期验收报告 |
| M3/M4 后续功能 | V；逐项补充设计与验收 | 发布、分支、完整影响分析及长篇能力；完整 V1 验收 |

C 与固定客户端 G 在存储接口稳定后可独立推进；采用用例、业务规则与数据库事务保持单一负责人。默认串行完成可验证切片，不因目录存在而提前铺全部功能。模型选型不阻塞 S；编辑组件选择不阻塞数据库与规则验证。

首期推荐路径：P01–P02 → S → C 与 G01–G04 → R01 → G06 → R02–R05 → V；P03 在 C 前完成，P04/G05 与 P05 在 V 前完成。三章续写依赖 R01 的正式状态，不能仅凭生成任务存在就勾选 G06。

## P 开发准备

- [ ] P01 将项目专属编码规则写入仓库级 AGENTS.md，并使用 uv 建立最小 Python 项目和启动入口。完成条件：规则引用 V0.2 边界；创建 `pyproject.toml` 与 `uv.lock`，环境目录不入库；`uv run python -m story_workbench --help` 可运行；不生成尚未使用的模块。
- [ ] P02 建立 pytest 测试入口和首个有效检查。完成条件：pytest 作为开发依赖由 uv 管理，更新锁文件；`uv run pytest` 实际执行至少一个有行为断言的测试；记录首轮 Python/macOS 版本；不把空测试通过当作验证。
- [ ] P03 选择并验证终端编辑组件。完成条件：中文多行输入、粘贴、光标移动、保存/取消可操作；新增依赖按项目规则处理。必须在 C 阶段实现编辑器前完成。
- [ ] P04 确定模型供应商、模型、密钥配置、上下文和输出限制、超时及预算。完成条件：记录非敏感配置和费用控制方式，密钥置于项目外；真实调用前完成。
- [ ] P05 准备真实试用故事和人工核对样本。完成条件：作者提供或认可素材，记录已知事实、传闻、持久设定及预期知识边界；V 阶段前完成。

## S 保存、审阅与采用

触点：domain、application/authoring/adoption/projects、infrastructure/database/files；按首次使用建立所需表与函数。模型输出先用固定数据。

- [ ] S01 实现项目打开、数据库初始化、schema 版本、项目锁及作品/章节关系约束。完成条件：重开项目数据仍在，跨作品/跨章引用被拒绝。
- [ ] S02 实现计划与正文不可变版本、当前编辑稿指针和历史恢复。完成条件：两稿均可读取；恢复创建新稿，既有历史不变。
- [ ] S03 实现外部文件对账和独立文件写入。完成条件：数据库稿与外部稿冲突时均保留；文件删除不变空稿；保存失败可恢复输入；不覆盖已有工作文件。
- [ ] S04 实现检查材料、已读声明与具体问题处理的准确版本绑定。完成条件：修改正文或相关依据后，旧检查/审阅不能授权新采用。
- [ ] S05 实现采用事务、授权校验和幂等操作。完成条件：一次提交保存审阅/采用/失效标记；重复请求不重复采用；失败无部分正式写入。
- [ ] S06 执行 T01–T04 并保存结果。完成条件：真实临时 SQLite 和文件上的版本、外部编辑、故障与隔离断言全部通过。

## C 作者交互入口

触点：cli、启动装配与 authoring/projects；AI 讨论接入在 G 阶段完成。

- [ ] C01 实现作品/章节选择、消息保存、候选想法和作者决定、计划编辑与全文查看。完成条件：作者可通过入口整理故事，候选不会自动成为决定或正式事实。
- [ ] C02 接入普通多行编辑器。完成条件：保存/取消行为正确，保存失败保留缓冲，全程不要求 Markdown 语法或手工文件路径。
- [ ] C03 实现检查展示、准确稿件选择与明确采用入口。完成条件：展示全文、新增设定、冲突及偏差；歧义“采用那版”不写正式记录；一次明确动作提交已读与必要授权。
- [ ] C04 人工执行 T05 并保存交互记录。完成条件：中文编辑与取消可用，CLI 操作绑定正确版本。

## G AI 任务与上下文

触点：application/generation、ai/context/tasks/prompts、infrastructure/provider；用注入的固定客户端验证，不绕过任务解析与证据校验。

- [ ] G01 实现纯上下文构建与依据持久化。完成条件：来源和遗漏可追溯；拒绝稿、未来章节知识和过时状态不能混入正式续写；新增规则使旧依据过时。
- [ ] G02 实现讨论、正式写作和试写任务合同。完成条件：最小输入可写，试写先展示缺口与假设，委托限本次请求本章；正常请求一次生成、一次检查，不自动润色。
- [ ] G03 实现检查与候选事实提取。完成条件：必填字段、枚举和原文引用受校验；假引用/截断结果不能标检查成功；提取不自动成为 Canon。
- [ ] G04 实现 run 阶段记录、流保存、取消与迟到结果保护。完成条件：只有已保存流块可恢复；取消先落库；迟到结果不能切换当前稿；同项目最多一个模型请求在途。
- [ ] G05 实现单个供应商客户端并接入真实配置（依赖 P04）。完成条件：协议、流、超时、取消及用量得到验证；不自动重试付费请求，密钥不进入项目数据和日志。
- [ ] G06 用固定客户端执行 T06–T08 的确定性部分（依赖 R01）。完成条件：三章调用次数、拒绝稿隔离、无效检查与容量边界断言通过；语义准确性留待 V02。

## R 状态、回改与失败恢复

触点：adoption、generation、projects、domain/rules、database/files。

- [ ] R01 实现正式快照计算、事实纠正和提交前依据复核。完成条件：只使用已采用且已审阅的候选及有效修订；保留传闻与主体认知，过时计算只存历史。
- [ ] R02 实现前章回改后的下游失效与逐章复核。完成条件：不自动改后章正文；未改正文可更新检查/审阅/状态，不新增正文或重复采用。
- [ ] R03 实现重启恢复与阶段重试。完成条件：未完成 run 标中断；检查失败只重试检查，重算失败保留采用；状态未恢复时阻止依赖续写。
- [ ] R04 实现一致性备份与新目录恢复。完成条件：正文、数据库、来源与任务进度一致；包含恢复文件且不含密钥；变化或校验失败不得报告成功，不覆盖原项目。
- [ ] R05 执行 T09–T11 并保存故障注入结果。完成条件：保存失败、取消迟到、重算竞争、后章复核和备份恢复均通过。

## V 首个可用闭环验收

首个闭环包含 M1/M2 和必要的基础恢复保护；尚不等于完整 V1。

- [ ] V01 用真实模型和 CLI 完成连续三章创作、拒绝稿重写、试写、编辑与采用。完成条件：保留操作记录及准确的正文/采用/状态引用。
- [ ] V02 人工执行 T07 语义样本，核对传闻、持久设定和推理不足。完成条件：逐条记录命中与遗漏；不以格式测试或模型自评代替人工判断。
- [ ] V03 实现按请求的阅读体验诊断与试改，并执行 T12。完成条件：有问题证据、修改选项和作者保留/拒绝理由；不覆盖原稿、不擅自变成整书规则；允许评价为不满意。
- [ ] V04 汇总首期验收报告。完成条件：T01–T11 确定性结果、T05 手动记录、T07/T12 人工记录、每章耗时/用量及已知限制齐全；未解决阻塞已处理，功能缺口明确。
