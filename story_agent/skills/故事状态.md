# 故事状态：定稿后怎么更新 故事状态.md

用在：一章定稿之后；或作者纠正了某个事实之后。

## 文件结构

```
# 故事状态
更新到：第N章

## 已成立的事实
（正文明确写出的事。每条一句，标注出自哪章。）

## 各人物知道什么
### 人物名
- 知道：…（哪章知道的）
- 不知道：…
- 以为：…（错误的认知也记，它决定他会怎么做）

## 读者知道什么
（读者知道而某些人物不知道的事，这是悬念的来源。）

## 未回收的线索
（埋下但没解决的事。每条标注出自哪章，回收后移到已成立的事实。）

## 时间线
（每章发生在什么时候，持续多久。）
```

## 规则

- 只记正文确立的事。人物的猜测、传闻写进"以为"，不写进"已成立的事实"。
- 每条标注出处章号，以后核对用。
- 作者在 决定.md 里定的事，如果正文还没写到，写进"未回收的线索"，注明"作者已定，正文未写"。
- 更新是改写，不是追加：过时的删掉，改变的改掉。这是自由文件，不用审批，改完在对话里说一句改了什么。
- 推倒重来时，作废章节带来的事实、认知、线索要一并清掉，不是留着标注"已作废"。
  留在文件里就会被当真。
- 更新完，大纲.md 里本章状态改为"已定稿"（这一步要审批）。
